# JUNTA implementation plan

> Execution: native, autonomous, authorized by the attached master prompt. Specification: consumer intent -> collective demand -> merchant offer -> notification -> affiliate click. Prioritize complete core journeys over incomplete peripheral features.

## Architecture and decisions

Modular monolith NestJS, PostgreSQL/Prisma, Redis/BullMQ, Next.js web/admin/merchant, Expo Router mobile, pnpm/Turbo. Integer cents at the API boundary and DECIMAL in PostgreSQL. UTC timestamps. Transactional outbox with retry and idempotent notification creation. Hashed rotating refresh sessions, Argon2id, role and merchant membership enforcement. Never trust client merchant scope. Browser tokens in memory, refresh via HttpOnly cookie; mobile secure storage. No payment processing.

Alternative considered: a single Next.js application would reduce initial setup, but would omit the requested independently deployable API and native mobile boundaries. Microservices add cost without business benefit.

## Visual direction

Portuguese consumer product with cobalt #2549eb, pale blue #edf2ff, white #ffffff, ink #172344, coral #ff775e and green #17765c. Rounded geometric system typography, strong short headlines, spacious catalogue with custom product illustrations and one prominent collective demand panel. Desktop catalogue alongside a large editorial headline; compact touch-friendly cards and bottom navigation on mobile. Operational portals use dense tables and clear forms.

## Review focus

- Concurrent duplicate intents must not inflate demand (integration race test).
- Refresh replay must revoke the token family (auth integration test).
- Merchant A cannot modify B and consumer/analyst cannot mutate admin resources (permission integration test).
- Expired offers cannot produce affiliate redirects (offer integration test).
- Outbox retries must not duplicate notification records (worker integration test).

## Task 1 — Foundation

Create package.json, pnpm-workspace.yaml, turbo.json, shared TypeScript/ESLint/format config, compose.yaml, .env.example. Pin dependencies in lockfile, enable required native builds. Verify pnpm install and compose health. Commit foundation.

## Task 2 — Database

Create apps/api/prisma/schema.prisma, initial SQL migration and development-only seed. Models: users, sessions, products/variants, intents, pools, merchants/memberships, offers, campaigns, outbox, notifications/devices, preferences, referrals, audit, analytics, remote config. Unique constraints and query indexes. Test migration on empty isolated database and migration deploy twice. Seed nine demo products and users with runtime-provided dev password. Commit schema.

## Task 3 — API core

Write real database integration tests first in apps/api/test/journey.test.ts and watch fail. Implement auth, catalogue, atomic intent/demand/outbox flow, sharing, merchant/admin offers, notifications, affiliate clicks and analytics. Shared validation schemas define API contract. Assert PS5 target 299900 cents, duplicate/concurrent intents, role/tenant isolation, token replay, expired offers. Build, typecheck, lint and test before commit.

## Task 4 — Clients

Create packages/api-client, packages/ui, apps/web, apps/admin, apps/merchant. Write Playwright journey first; implement search, public product pages, signup/login, intent form, my products, inbox, share, admin catalogue/campaign/offer and merchant demand/offer dashboard. Metadata, OG, sitemap, terms/privacy placeholders. Verify production builds and browser journey with actual PostgreSQL data. Commit web and portals separately.

## Task 5 — Mobile

Create apps/mobile Expo Router onboarding, auth, catalogue/search, product, intent, my products, offers, settings/deletion, secure sessions, notifications registration, deep links and network retry. Configure EAS profiles and provisional assets. Export Android/iOS/web; run Expo Doctor; add Maestro core journey. Native runtime/build claims require actual device or EAS evidence. Commit mobile.

## Task 6 — Operations and release

Container multi-stage API and worker; integration CI with fresh PostgreSQL/Redis, mobile export, frontend builds, security audit. Add deployment/env/backup/restore/rollback docs, test complete compose stack, scan secrets and dependency vulnerabilities, verify clean installation. Push branch regularly and create PR; check actual CI result. Use connected Vercel capabilities if access permits previews; no paid provisioning. Verify real preview URLs. Attempt EAS identity/build only if account access exists. Record exact external blockers and final matrix without claiming unverified components ready.
